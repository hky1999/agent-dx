# 自动内存控制

中心协调器 Coordinator 的源码位于 `platform/coordinator/`，节点代理 adxlet 的源码位于
`platform/adxlet/`。Coordinator 根据节点完整物理观察决定目标，在原宿主预算中持久预留；
adxlet 在已有 Environment 串行控制器中更新本地占用，然后调用 sandboxd 的条件资源操作。
创建、增长和恢复共用持久预算，没有另一份可发放容量。

## 配置与准入

Coordinator 配置省略 `memory_control` 时，不生成新的自动调整操作，但仍允许完整观察和
原操作结算。显式启用的配置如下，所有字段均有下列默认值：

```json
{
  "memory_control": {
    "grow_per_mille": 650,
    "shrink_per_mille": 300,
    "target_per_mille": 500,
    "cooldown_millis": 5000,
    "low_usage_millis": 30000,
    "low_usage_samples": 5,
    "max_sample_age_millis": 10000,
    "operation_timeout_millis": 10000
  }
}
```

另外必须配置可信 `host_budgets`。公开创建 HTTP 请求通过
`"elastic_memory": {"high_per_mille": 750}` 显式启用；Python SDK 对应
`Sandbox(cpu=500, memory=128, mem_limit=256, elastic_memory=ElasticMemoryPolicy(750))`，
其中 `ElasticMemoryPolicy` 从 `adx_sandbox` 导入。请求内存是出生额度和下限，
执行限制是允许上限；省略或传入 null 保持固定执行额度。
此字段映射到内部 `sandbox.elastic_memory`，不接受未知策略字段、非法比例或不支持的运行时。
节点注册通过独立的
`memory_control_version=1` 字段声明能力；旧节点、未知能力版本和用户标签均不能授权弹性出生。
带弹性配置的调度禁用不检查此能力的聚合优化，持久准入再次检查实际节点能力。
仅支持 runsc，不支持从 snapshotId 克隆；内存取整数 MiB，上界不超过 2^53 字节，
memory.high 至少为 4096 字节。实际 CPU 配额至少为 10 millicores，CPU 与磁盘保持执行上限。
sandboxd 的 `[plugin.resource].memory_high_ratio` 必须与请求一致，例如 0.75 对应 750。
这是 daemon 全局配置，也会影响该 daemon 新建的固定额度沙箱的软节流阈值；不会改变其硬上限。
`memory.high` 不是绝对 OOM 保护。只有 SDK 选项不会自动打开中心策略；未启用中心策略时
弹性实例保持出生额度。旧公开服务器可能忽略未知字段，因此必须部署匹配的服务端和 SDK，
并以实际出生额度和物理回读验收，不能只根据创建返回成功判断启用。

## 决策与结算

`CoordinatorService.ReconcileMemory` 只接受已认证的归属节点及当前会话。
完整观察携带 Assignment、Runtime、sandbox ID、资源代际、revision、上次操作编号、
CPU 配额、memory.max、memory.high、用量、冻结和操作完成事实。未知、冻结、错误代际、
错误比例、过期或来自未来的采样均不能生成新授权。压力计数只是观测，不单独触发修改。

用量达到增长阈值时，目标按照目标使用率计算，并向上取整到 MiB；一次增长不超过当前上限的
两倍，且受规格上限和共享预算约束。容量不足保留当前占用，返回没有新授权的完整账户。
缩容要求不少于指定次数的不同低用量采样，并持续达到低用量窗口；计数间隔至少一秒。
采样中断超过新鲜度窗口时重新计数。重复时间戳不累计次数。低用量窗口随中心账户持久保存。
每次授权之后有冷却期。目标也不能低于出生内存。

增长预留和操作意图通过同一 Redis 比较更新原子写入。缩容派发不归还预算，只有精确目标
回读、对应 revision／操作编号以及解冻确认后才结算。回复丢失保留 source 和 target 的较大值，
下一次完整观察可以结算实际完成的原操作，不再次执行。原期限和原授权不续期。
中心重启或节点进程替换后，当前已认证会话可以结算原授权的精确结果；旧会话不能写入，
新会话也不能派发原会话授权。结果仍未知时保留预留；无法形成完整结果的部分写入仍需已有条件物理退役路径归还。

节点关闭准入或被运维暂停后，当前仍可路由的归属会话可以提交新鲜完整的物理观察，
并结算已有授权的精确完成或未改变结果。新建及显式、自动资源调整仍须通过准入检查；
中心不会在本次结算中生成新的增长或缩容授权。返回尚未结算的原授权只供结果核对，
不会续期或提供重新派发许可。旧会话、错误物理代际、不完整结果和未知占用的检查保持。

新的资源派发先更新本地 Runtime 占用，再进入 sandboxd 适配器；本地容量不足、压力或容量观测过期
会拒绝增长派发。节点结果日志不提供离线资源授权。物理操作与删除、暂停和恢复共用串行边界。
节点重开后的保守预留可通过中心完整账户收敛，其他 Runtime 的占用保持不变。
退役后中心重新读取持久账户，避免调度缓存保留已删除的动态额度。

## 恢复额度

弹性实例从检查点恢复前，中心和节点已经按规格内存上限预留。发给 sandboxd 的恢复请求使用
这份已预留上限，为检查点载入提供额度；原策略的出生下限、允许上限、CPU 和请求指纹保持不变。
sandboxd 核对源检查点保存的策略，并限制恢复额度不能超过源策略上限。普通新建仍按出生下限，
固定额度恢复保持其原请求。过期授权不能派发恢复，节点日志重开后只重放原操作结果。

恢复后的 Running 状态不单独归还预留；必须核对新 Runtime、物理代际及完整资源观察。
之后由持续低用量窗口和条件缩容逐步归还，不能把检查点文件大小当成恢复内存峰值。
这是保守使用已有上限的恢复策略，没有新增共享容量，也不保证任意负载在该上限内恢复成功。
实际载入峰值、内核 memory.peak、memory.high／max 和恢复全阶段预算仍需物理验收。

## 过期和没有改变额度的操作

节点对过期、旧节点会话或旧中心 epoch 的授权只调用 `ResolveResourceOperation`，传递原完整请求和原截止时间；不能续期或重发扩缩容。操作尚未执行且未过期时，服务端仍拒绝结算。原期限已过且完整源资源、代际、修订号及解冻事实匹配时，sandboxd 在原物理锁内持久登记该请求不再执行，递增修订号并保存原操作指纹，全程不写资源上限或冻结状态。本地增长准入关闭不能阻止这类结果核对。

中心只接受原操作编号和下一修订号下的两个完整终态：目标已经执行，或上限与 memory.high 均保持原值。后者持久保存为 `unchanged=true`，增长归还未用预留，缩容保持原额度；不得把它重放成目标成功。预算存储 schema 6 保存这个区别，重启后继续生效。只有旧数值、时间已经过期、日志仍未关闭、冻结或部分写入都不能作为终态。

节点先保存原请求指纹，再查询服务端；回复还须经过独立 Stats 核对。回复丢失或节点日志重开后可以从精确终态继续结算；未知结果继续保留原预留。sandboxd 恢复线程取得物理锁后重新读取持久记录，避免旧扫描结果覆盖后续修订号或使用过时的冻结归属。

## 部分写入失败和生命周期推进

过期操作的原请求保存在节点持久日志中。资源核对失败后，节点可再次核对该请求的守护进程终态及独立 Stats；只有同一物理代际、原操作编号、下一修订号、日志关闭、确认解冻、CPU 不变，并且 memory.max／memory.high 是原源值和目标值的混合，才将这次执行转入已有失败清理流程。这个结果不是扩缩容成功，不直接归还预算，也不重新派发过期请求。条件物理退役失败或结果未知时继续占用，后续生命周期检查重试清理；已经配置的重启或 failover 仍通过原持久恢复授权路径。

没有原持久请求、期限未到、冻结未解除、日志未关闭、服务端回复丢失、回读变化、外来身份或任意外部数值都不能触发这条失败路径。内存控制报错也不阻止独立的空闲检查；只有配置了空闲删除且原有完整活动观察连续满足空闲窗口时才删除。活动在内存 RPC 完成或超时后重新采样；活动未知或仍有请求时重置空闲窗口，保持执行与预算。

## 验证范围

源码测试包括真实 Redis 下的共享预算、持续观察窗口、会话替换和未知占用；
节点模拟运行时下的派发顺序、回复丢失、中心不可用、本地准入；以及 mTLS RPC 的鉴权、
授权、结算和退役。sandboxd 适配器另有真实 Unix socket 服务测试。
这些测试不代替物理验收；匹配生产构建、部署、公开入口与恢复峰值的物理验收、
完整冻结与组件故障矩阵、25 次资源双周期和25次正值预算退役仍须完成。
