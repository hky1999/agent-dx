# 宿主服务和检查点开销预算

宿主服务、检查点和恢复峰值与沙箱创建、扩容共用一份物理宿主容量、Redis header CAS和AOF落盘确认。退役历史归档使用schema13；旧程序拒绝该格式。升级前先暂停参与节点并固定运行字节、当前epoch、全部库存和七类开销归属，不混用旧写入者。源码、构建、部署和物理验收分别登记。

受信任宿主控制器在创建服务或检查点之前调用私有程序`adx-overhead-budget`。程序只读取Coordinator配置中的`redis_url`与`namespace`；stdin最多3MiB，含`op`、`epoch`和`id`。`inspect`回读宿主预算、热预留、`history`及可选环境的身份和检查点摘要。`attach`只绑定现有epoch，不初始化存储或增长epoch。此入口有直接存储管理权限，不向任务开放，不输出配置或凭据。

`reserve`携带`reservation`：`host_id`、`owner_sha256`、`resources`及空`retirement_proof_sha256`。所有者摘要关联外部不可变物理描述：Linux启动、父分组、服务身份、运行目录、源码程序摘要和检查点操作。CPU和内存为正值，磁盘可为零。同一ID的完整活动请求重放不重复占用；变更归属或额度拒绝。重启、过期、未知结果和节点离线均不归还额度。

最多保留512个热身份，包括尚未归档的退役记录；满时拒绝新身份。首次归档前，身份规则保持原格式。归档后新身份必须为`oh-{history.generation}-{suffix}`，代次使用无前导零的十进制，完整ID仍限128个ASCII字母、数字、下划线或连字符。首次代次大于所有现存、符合该格式的旧身份，防止旧的未来代次前缀被再次接纳。活动旧身份的精确重放与结算继续有效。旧代次、未来代次、无代次和已归档身份都不能取得新预留；恢复峰值入口执行同样的检查。

`retire`携带原`owner_sha256`和`retirement_proof_sha256`。调用方先核对完整物理归属，证明整个cgroup及子分组为空，并确认运行文件、制品和引用完成结算。仅提交摘要不能替代物理证明。未知结果保持额度；热记录中的同一完整结算幂等，不同证明冲突。尚有未决执行链接的恢复峰值不能单独退役。归档后的退役ID返回不存在，不通过重放重新生成记录；完整原证明从已接收归档审计。

`archive_prepare`是只读操作，可传`protected_ids`。它返回`archive`、`archive_json`和`archive_sha256`。规范字节是UTF-8 JSON、递归按键排序、无尾部换行；摘要对应这些字节。归档含原Redis权威、源epoch、下一身份代次、上一链头、受保护身份清单及所选完整退役记录。受保护身份必须仍存在，不能同时选入删除；清单持久保存在链头，后继准备自动合并，普通归档不解除既有保护。外部所有权链仍需直接回读的退役记录必须保护，直到调用方另有经过验收的归档解析器。

调用方先在已预留的持久存储中保存全部规范字节、fsync文件与父目录，独立核对摘要、物理所有者、容量和引用，保存接收证明。然后以`archive_commit`提交原`archive`及`acceptance_sha256`。此摘要是受信任管理员的完整接收声明，存储端不会代替管理员检查外部文件。未接收和接收未知时不得提交。

提交核对原权威、epoch、链头、代次和每条退役证明，经单次header CAS删除所选热记录并推进schema13链头；活动记录、受保护记录、执行链接和其他字段保持。Redis只保存有界链头和累计退役数；完整永久凭据由预算内的外部接收者持有，不把历史无限堆回Redis。头比较失败不删除任何记录。相同最近归档及接收摘要的丢回复重放回读原链头，可跨Coordinator重启；不同接收证明或已经被后继归档覆盖的旧请求拒绝。归档前一切未知占用仍为活动记录，不可选入归档。

完整账本导致构建角色也无法登记时，受限维护计划工具`build/maintenance/overhead_archive.py`只生成一次schema12到13的转换计划，不联网。输入是一份同一原子读取的完整预算视图；部署者必须证明没有Environment、全部物理库存为空、节点暂停，未投影字段只能是已摘要的停车日志。先准备并接受完整归档，再从新鲜视图生成计划，只能附带一项明确所有者的构建预留；CPU、内存和磁盘仍逐宿主校验原容量，活动行不改写。实际提交复用`platform/coordinator/src/storage/overhead_archive.lua`同一不透明头CAS。维护期间旧程序拒绝schema13，完成已计费的新程序构建和部署后才恢复工作。该单次路径不构成一般资源准入接口，不能重复执行或回退schema。

运行服务及长期元数据继续持有对应预留，available可以小于总池容量。`memory_accounts.overhead_bytes`与出生、已结算扩展和在途扩展构成互斥占用；未知和恢复统计是重叠诊断视图，不能再次相加。

停车中心记录沿用schema11的持久语义，与预算共用header CAS、epoch隔离和AOF确认。`journal_read`／`journal_write`传递`id`、`owner_sha256`、`expected_revision`与`journal`；单日志最多2MiB，含对应revision、存储身份和最多32项操作，最多16个控制器身份。相同丢确认请求只回读原提交，旧版本、不同归属或不一致摘要拒绝；中心确认先于外部动作和本地缓存确认，中心缺失、回退和冲突均拒绝恢复。响应正文和凭据不放入中心记录。

`queued_reserve`返回的`coordinator_epoch`属于固定目标执行的原签发身份，后续重启不能替换为当前中央epoch。恢复操作、源revision、目标Runtime、节点会话及原截止时间共同保存；不能以数值相等推断归属。恢复峰值与替换执行原子预留，拒绝时两者都不提交。
