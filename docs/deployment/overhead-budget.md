# 宿主服务和检查点开销预算

Coordinator的持久预算schema10将宿主服务及检查点预留与沙箱创建、扩容及恢复计入同一宿主容量。配置容量不变；每次预留在完整Redis快照上计算，并通过同一header CAS提交，Redis确认仍要求本机AOF落盘。旧schema9写入者拒绝schema10，不能混用旧Coordinator。

受信任宿主控制器在进程启动、临时检查点分配之前调用私有程序adx-overhead-budget。程序读取现有Coordinator配置，只使用其中redis_url与namespace；stdin最多3MiB，含op、epoch和id。inspect回读宿主预算、预留及可选环境的身份与检查点摘要字段，不输出配置、凭据或环境变量。attach只绑定现有epoch，不初始化存储，不增长epoch。该入口具备直接存储管理权限，不能暴露给任务。

reserve携带reservation对象，包含host_id、owner_sha256、resources和空retirement_proof_sha256。归属摘要对应外部不可变描述：Linux启动、父分组、进程服务身份、运行目录、源码程序摘要及检查点操作。CPU、内存为正值，磁盘可为零。同一ID完整重放不重复占用，改变归属或额度拒绝。服务重启、过期、未知结果或节点离线不会归还额度。最多保留512个身份，满后关闭新身份。

retire携带原owner_sha256及retirement_proof_sha256。受信任调用方必须先核对原物理归属、确认整个cgroup及子分组为空，并确认运行文件、临时文件、检查点引用已经清理；仅传一个摘要不能替代物理证明。程序不从用户HTTP接收此类证明。结果未知保留原额度；同一完整结算重放幂等，不同证明冲突。结算后保留拒绝记录，该ID不再重用。检查点峰值预留在制品清理前继续占用，不能仅按最终文件大小提前归还内存。

运行服务及长期元数据必须继续持有对应开销预留；available因此可以小于总池容量。memory_accounts.overhead_bytes与出生、已结算扩展和在途扩展共同构成互斥内存占用，未知及恢复统计仍是重叠诊断视图。

停车编排的中心记录使用schema11，与容量及服务预留共用原Redis header CAS、epoch隔离和AOF确认。私有journal_read／journal_write接口传递id、owner_sha256、expected_revision及journal；journal是最多2MiB的schema1对象，含对应revision、宿主存储identity和最多32项operations。每个命名空间最多16份控制器身份，不在线删除或重用。完全相同的丢失确认请求只回读原提交，不重复推进；旧版本、不同归属或不一致摘要拒绝。旧schema10程序拒绝schema11，不能混用。宿主文件只是原盘恢复见证：中心确认必须先于外部动作和本地cache确认，中心缺失、回退或归属冲突拒绝恢复。响应正文和凭据不得放入中心编排记录。

queued_reserve的成功授权另返回coordinator_epoch，表示该执行授权最初签发的持久代次。该值属于固定目标执行身份，在Coordinator随后重启时不能用新的中央header epoch替换；当前控制器epoch另用于存储围栏和短期投递许可。调用方须将恢复操作、源revision、目标Runtime、节点会话和原截止时间共同保存，不能只按数值恰好相等推断归属。此输出只用于受信任宿主控制器，不向任务暴露Redis配置或直接发放预算。
