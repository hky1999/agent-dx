# 宿主压力准入与存储恢复契约

Coordinator配置可选 `host_pressure_admission`，按 `host_budgets` 的完整宿主集合配置 `adx_core::pressure::PressureSource`。各节点配置同一来源的 `host_pressure`。默认不启用；显式安装后中心存储版本提高到9，旧程序拒绝写入。后续启动必须提供完全相同的来源配置，省略或改变来源不能静默停用准入。

来源配置示例见 [host-pressure-source.json](../../build/config/examples/host-pressure-source.json)。部署者必须从原主机、父cgroup和持久目录生成实际身份，不能使用示例身份开放准入。`path` 在中心和节点中指向同一个只读挂载目录下的文件；宿主观察者是唯一写入者。文件必须是至多8192字节的普通文件。身份、版本、完整字段、有效期或内容不符，来源不存在、软链接、过期或明确关闭，均返回 `NoCapacity`。时钟早于观测时刻也关闭。来源有效期上限由 `max_age_millis` 固定，允许100至60000毫秒；部署策略应选择短有效期。

观察者绑定宿主ID、观察者权威、Linux boot ID、父cgroup的device／inode，以及持久目录身份清单的SHA256。每份观测包含序列、起始采样时间、到期时间、准入状态、原因及宿主／父cgroup内存、内存PSI和磁盘余量。原子发布、单写入者、连续低水位恢复窗口及采样失联处理由配套部署观察者实现。中心和节点只读取观测，观测本身不授权修改资源或归还预算。

创建、本地声明、跨节点恢复和本节点执行恢复在同一持久预留事务中检查宿主观测；扩容也在预留事务中检查。节点取得授权后，在最终分配和每次扩容派发前再次读取。压力变化与物理调用之间仍有有限竞态窗口，压力门不代替持久严格预算、操作deadline和物理回读。

关闸不清空预留，不使执行自动消失，也不取消未知操作。精确物理回读、已确认未修改、缩容、退役和结算继续执行。节点收到仍在有效期内的旧扩容授权但宿主准入关闭时，只尝试解析物理结果；没有确认前保持中心预留。已经发生的扩容可按精确观测结算，不重复派发。

`Session::host_budgets()` 的Rust存储视图增加 `memory_accounts`：`birth_bytes + settled_extra_bytes + in_flight_extra_bytes` 等于持久内存占用；`competing_ungranted_bytes` 是上限以内尚未授权的竞争需求。`unknown_result_bytes` 和 `restore_in_flight_bytes` 是占用的交叉视图，不能再次相加。现有公开宿主预算协议继续返回总容量、占用和剩余量，未增加这些分项字段。物理使用和峰值必须独立采样，不能用逻辑预留代替。

自动恢复仅承诺同一启动身份及保留原Redis、节点SQLite和守护进程状态盘的进程恢复。AOF及 `appendfsync always` 不等于整机掉电承诺。主机重启、丢盘和备份恢复要求隔离新准入，保留未知占用，核对全部物理代际后重新建立权威。当前没有备份之外的不可回退水位，不承诺自动识别中心与节点共同回退到一致旧备份，或原文件在同一启动期间被原地回退。

当前控制、检查点及恢复余量没有独占预留证明，不能把父cgroup上限与工作负载预算之差、服务 `memory.max` 或瞬时空闲内存写成独占保证。恢复继续预留允许上限，压力门只决定是否接受新工作，不提高预算，不启用硬上限超卖或自动停车。

验证入口包括 `cargo test -p adx-core --test pressure`、`cargo test -p adxlet --test resources`、`cargo test -p adxlet --test memory_control`，以及专用真实Redis上的 `cargo test -p adx-coordinator --test storage pressure -- --ignored --test-threads=1`。这些检查与目标环境物理验收分别记录。

新增自动策略仍要求节点完整可用，不能用压力门替代容量新鲜度、维护状态和生命周期对账。节点不通告可用时，只继续既有授权的回读、结算和安全缩容，不生成新的自动调整。显式存储层新增缩容仍要求节点准入可用、当前可路由归属及完整物理来源；已授权缩容的结算不要求重新开放准入。

当前文件来源契约用于同一Linux物理宿主。消费端独立核对实际boot ID，即使旧观测文件尚未到期也拒绝其他启动身份；跨物理宿主的观测分发与验证不在本包范围。
